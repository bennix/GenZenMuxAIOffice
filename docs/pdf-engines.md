# PDF 原生翻译与字体段落工作台

编辑工具栏提供“整篇保版翻译”和“字体与段落工作台”两个入口。实现采用 TypeScript 与应用已打包的 PDFium / HarfBuzz WASM、字体资源，不调用 Python，也不在首次使用时安装外部 CLI。功能参考 PDFMathTranslate 的版式翻译思路和 PdfCraft 的可验证编辑流程，并非完整移植上游所有工具。

## 字体

优先保留 PDF 内嵌字体；内嵌子集缺少字符时，查找本机原字体或同族字形。解析 PDF 子集前缀和常见粗体、斜体名称。找不到可覆盖文字的同族字体时，拒绝该项修改并提示安装原字体或明确选择其他字体，不自动换成其他字族。

工作台“同族字库检查与下载建议”显示原字体、本机覆盖情况及字体来源建议。下载建议不代表授权，也不自动下载字体。安装后重新启动应用以刷新系统字体索引。可手动导入字体；导入时检查字体嵌入限制。系统字体扫描覆盖 macOS、Windows、Linux 的常用字体目录；不同平台的实际字库需分别验证。

## 段落与翻译

工作台使用实际字体测量换行，提供字号、宽度、行距、字距、缩放、位置等调整，保存前检查布局并核对回读文字。提供渲染预览、撤销重做和文件导出。复杂扫描件、文字轮廓、特殊字体编码、复杂公式和表格仍需人工预览确认。

翻译调用用户配置的系统 AI，可指定页码和目标字体，输出单语与原译交替双语 PDF。逐段翻译、逐段写入并校验，不缩小字号或压缩行距。译文超出段落空间时保留原文，在原处添加包含完整译文的标准 PDF Memo 文字批注，并继续后续段落；翻译报告记录批注位置。无可用字体、保护标记变化或回读失败时应报错。网络临时故障最多自动重试五次。AI 翻译需要已配置可用的模型服务；内置 PDF 引擎不代表离线语言模型。

## 验证范围

字体定位及文字编辑测试覆盖子集字体名、同族查找、显式中文字体、缺字体拒绝、原文件保持和独立文字回读。原生工作台及翻译管线仍需完成端到端回归，不能视为所有上游能力已完成验证。

## Nimbus Roman 内置字库

应用内置 URW Nimbus Roman 常规、粗体、斜体和粗斜体，识别旧名 NimbusRomNo9L-Regu / Medi / ReguItal / MediItal。使用同一字体家族，无需用户首次下载。安装包构建检查四个字体及完整授权文件是否存在。

这些西文字体不包含中文字形。保留源字体模式下，若原字体无法覆盖译文，保留原文并在原处添加完整译文 Memo，继续后续段落；报告通过 fontMemos 记录位置。要将中文写入正文，请明确选择内置 Noto 宋体或黑体。字体原文件未修改；授权为 AGPL-3.0，带 PDF/PostScript 文档嵌入例外，完整条款及对应源代码地址随字库分发。

## 翻译字体与日志

译文界面默认选择“按目标语言选内置字体”：中文正文按源字体类别选择 Noto 宋体或黑体，不缩小原字号。该选择允许替换目标语言字库；用户仍可明确选择“严格保留源字体”，此时缺少中文字形会保留原文并附 Memo。公式附近只拆分受影响的行，不把整段正文拆成小碎片；翻译前合并物理换行及英文断词。图片区域内文字不改写，正文换行不得占用下方图片空间。

进度日志按行输出每段原文、完整译文、公式/特殊对象保留文字及写入结果，界面限制滚动区域高度。最终结果目录包含 translation-log.txt。公式及图表保留原 PDF 对象，日志中的公式为提取文字，不代表重新生成公式图片。

所选译文字体缺字与源字体缺字均作为可恢复情况处理，不中断整篇翻译。自动字体模式下，简体中文先尝试推荐的 Noto 字族，再尝试另一内置中文 Noto 字族；明确指定字族时不自动替换。仍无法覆盖时保留原文、添加完整译文 Memo 并继续，日志列出缺字字符及 Unicode 编码。此行为不改变原有公式和图表对象。

段落级定位、译文校验、写入或回读校验失败时，保留该段原文，尽量附上完整译文和失败原因 Memo，并继续后续段落。未通过校验的候选 PDF 字节不会进入最终结果。失败信息记录在报告 skippedParagraphs 及日志中，完成摘要明确显示跳过数量；用户取消不会被当成普通跳过处理。文件整体无法读取、模型服务连接/认证失败或最终导出失败仍需报错。段落归属按实际行及横向覆盖判断，并去除同位置重复段落，避免同一原文被处理两次后引发定位失败。
