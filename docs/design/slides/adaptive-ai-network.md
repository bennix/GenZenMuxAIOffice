# Shared adaptive networking for built-in AI

All built-in main-process AI clients use `aiFetch`: chat/streaming, slide planning and page generation, document review, image/media generation, SystemOne, supervisor/screenwriting and web/image search. The Electron host installs the shared adapter lazily. The shell's LoveArt AI/research requests cross a bounded, cancellable IPC bridge and then use that same adapter; API keys are never logged by the adapter or put in proxy probes.

Each service origin gets a route cache (30 seconds). Detection tests the actual endpoint path with unauthenticated GETs, without original query parameters, cookies or body. Candidates include Chromium system/PAC settings, direct networking, credential-free proxy environment variables, and listening common loopback ports (HTTP and SOCKS5). Probes are bounded to 3.5 seconds. A 401/405 is evidence of reachability only, not working credentials or stable long-form streaming. Authenticated proxies requiring a login flow are not automatically configured; uncommon local ports must be exposed through system proxy settings or a supported environment variable.

A transport failure or truncated response stream invalidates the cache and cools down that route for 30 seconds. The next request reselects a route; it does not blindly replay a potentially billable POST. 401/403 provider responses are not treated as permission to retry authentication or bypass server policy. User cancellation is propagated. Offline detection reports failure without preventing the app from starting, quitting any app, editing shell configuration, or changing macOS proxy settings. Dedicated in-memory Electron sessions isolate routes from the main browser session.

`getAiNetworkStatus()` returns only mode/state/time, with no proxy endpoint, username, token or request content. LoveArt's preload additionally exposes `aiNetwork.status()`. Its buffered bridge supports its current non-streaming REST calls with a 32 MB request / 64 MB response limit and a three-minute timeout; streaming provider calls continue using native streams. Browser-only LoveArt uses normal browser networking. External MCP servers, arbitrary user scripts and third-party CLI child processes manage their own networking and are not silently reconfigured by this layer.

Tests simulate secret-free probes, concurrent discovery, fallback, cache expiry, stream truncation, no automatic POST replay, total failure, cancellation and the LoveArt bridge. Live authenticated generation and packaged cross-network switching still require manual acceptance tests; passing an unauthenticated probe is not a claim that every network will work.

## Settings and online updates

The shell exposes **Settings → Network & proxy** with Auto / System / Direct / Manual modes, a credential-free HTTP/HTTPS/SOCKS5 proxy field, last selected route/time and a **Save & check now** action. Preferences are atomically persisted to `ai-network.json` in app userData with user-only file permissions. New requests use changed preferences; existing streams are not killed. Manual mode is explicit and does not silently fall back to direct. A manual check targets the saved ZenMux base URL's models endpoint, never sends the API key, and explicitly distinguishes reachability from authenticated generation.

**Settings → About & online updates** has a visible **Check for updates** action. It reuses the existing signed-package updater, channel selection, download/install dialog and manual-download fallback. The updater's private Electron session is configured through the same route selector before checks/downloads. It does not install an update without the existing user action and does not modify the OS proxy. Source changes must be built and distributed as a new application release before installed copies can obtain them through the update feed; no release was published by this work.
